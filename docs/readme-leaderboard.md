# README leaderboard maintenance

The approved Leaders and Laggards tables are generated by `scripts/update_readme_leaderboard.py`, not written by a model. Only the `MODEL-LEADERBOARD` managed block immediately above Explore the results is replaced. Full versioned display names and nonbreaking spaces are retained. GitHub controls cell padding and responsive wrapping.

## Daily integration

The model-run finalizer publishes consensus, usage and the cumulative summary first. Pulse judging is a separate downstream job triggered by those reports. Therefore the README refresh cannot wait for judging before publishing the reports that trigger it.

The finalizer runs `python3 scripts/update_readme_leaderboard.py --if-ready` after copying its reports into the repository. If all inputs exist, include README.md in that batch commit. Otherwise retain the previous dated snapshot.

The GitHub Actions workflow `readme-leaderboard.yml` is the final, event-driven publishing step. It runs when summary, consensus, usage or Pulse JSON changes, including later cohort revisions. It uses current main, generates only when the five selected batches have matching complete Pulse panels, and commits only README.md. Missing inputs leave the prior explicitly dated snapshot untouched; the next upstream publication triggers another attempt. Malformed inputs fail visibly. Concurrent workflow runs are serialized. Push conflicts fail without force-pushing; rerun on current main. Manual workflow dispatch is also available. README-only bot commits do not retrigger the workflow.

## Exact calculations

- Window: latest five observed consensus batch dates from the latest dated cumulative summary audit, including that audit's date. Not five calendar days and not each model's latest five runs.
- Eligibility: at least three nonmissing observations per model for the specific metric in that window. Missing values are not zero. A new model with fewer than three observations does not enter that metric's rankings or All columns.
- Selection, cost, elapsed time and total tokens: arithmetic mean of each model's available values from the summary audit. Existing historical costs are not repriced; time is the summary's worker timing, and tokens include cache.
- Editorial: each day's equally weighted judge-panel mean, then an equally weighted mean of observed days. Every declared judge must score exactly the declared cohort, matching the models with selection scores for that date.
- Consistency: sample standard deviation of each model's daily editorial panel means, not mean judge disagreement. Lower SD means less variation, not necessarily better writing.
- All Avg: equally weighted mean of eligible model means. All Low and All High: their extrema. For consistency these are the mean/min/max of model SDs.
- Selection and editorial score: higher leads. Cost, time, SD and tokens: lower leads. True unrounded ties show all tied models; counts are annotated if they differ. Unknown future model IDs retain their complete canonical slug rather than guessing a display name.
- Preserve approved column order: Category, Model, Mv Avg, All Avg, All Low, All High, Runs. No judge-grading table.

Run without `--if-ready` for a strict readiness check. `--output PATH` writes the standalone sample without changing README. Standard library only; no provider calls, model execution or credentials required for calculation.
